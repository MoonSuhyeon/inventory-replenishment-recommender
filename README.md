# inventory-replenishment-recommender

**발주하지 않으면 얼마를 잃는가**를 품목마다 금액으로 매기고, 손실이 큰 품목부터 사람이 검토하게 하는 발주 추천 도구입니다.

ERP는 자동주문을 계산합니다. 이 도구는 그중 사람이 봐야 할 품목을 가려내고, 권고 수량과 근거를 보여 줍니다. 사람이 결정하면 주문서 파일을 만들 뿐, ERP에 직접 쓰지 않습니다.

> **상태: 개발 중 (MVP).** 가상 데이터로만 검증했습니다. 실제 운영 데이터로 맞는지 확인한 적이 없고, 아래 규칙은 그 확인을 거쳐야 하는 가정입니다. 정확도 수치는 주장하지 않습니다.

## 핵심 아이디어: 발주는 손실을 막는 의사결정

"재고가 부족한 품목을 찾아 발주량을 추천한다"에서 한 단계 나아가, 이렇게 정의합니다.

> 각 품목을 지금 발주하지 않았을 때 앞으로 생길 것으로 예상되는 손실을 금액으로 계산하고, 그 손실이 큰 품목부터 발주를 검토한다.

수량이 아니라 금액으로 비교하는 이유는, 부족 수량이 많은 품목이 손실이 큰 품목이 아닐 수 있기 때문입니다.

| 품목 | 예상 부족 | 예상 손실 | 부족 수량 순위 | 손실 금액 순위 |
|---|---|---|---|---|
| A | 50개 | 150,000원 | 2 | **1** |
| B | 20개 | 80,000원 | 3 | 2 |
| C | 100개 | 50,000원 | 1 | 3 |
| D | 10개 | 30,000원 | 4 | 4 |

(설명용 예시이며 실제 데이터가 아닙니다.)

### 계산 흐름

```
판매 데이터 → 판매 속도(수요) 추정
          → 현재고 + 입고 예정 − 앞으로의 출고 → 재고 부족 시점 예측
          → 미발주 시 예상 손실 금액
          → 품목별 손실 순위 → 발주 우선순위
          → 적정 발주량 추천 → 사람 검토 → 주문서 파일
```

### 손실만 보면 위험한 이유
손실이 큰 순서대로 무조건 발주하면 안 됩니다. 발주에는 제약과 반대편 비용이 있습니다.
최소 주문 금액, 소비기한, 이미 들어올 물량, 발주 가능 요일, 공급 리드타임, 폐기 위험.
그래서 최종 목표는 "미발주 손실이 큰 품목을 우선하되, 과잉재고·폐기 비용과 제약을 함께 보고 발주 조합을 정한다"입니다. 발주 전후의 기대 손실을 비교해 **어떤 품목에 얼마를 발주해야 손실이 가장 많이 줄어드는가**를 푸는 문제입니다.

### 현장 질문에 답하는 형태
"요새 나가요?" 같은 질문에 이런 문장으로 답하는 것을 목표로 합니다.
> 최근 판매가 늘었고 현재 재고로 1.2일을 버팁니다. 공급 리드타임은 2일입니다. 미발주 시 예상 손실이 검토 대상 중 가장 큽니다. 40개 발주를 권고합니다.

## 지금 구현된 것과 아직 아닌 것

| 항목 | 상태 |
|---|---|
| 발주 검토 큐 (하루 상한 안에서 급한 순 정렬, 상한 밖 부족 품목은 따로 모아 필요 시 끌어올림) | 구현 |
| 예상 품절 시점 묶음: A(이미 품절) → B(다음 입고 전 품절) → C(운영 기간 중 품절) → D(안전재고만 부족) | 구현 |
| 같은 묶음 안 정렬: 필수품목 → 일평균 판매금액 큰 순 | 구현 (**손실 금액의 간이 대용**) |
| 권고 수량: 책임 기간 판매 + 안전재고 − (재고 + 입고예정), 발주 단위 올림, 소비기한 상한 | 구현 |
| 신규·공급재개, 직접 주문, 계속 품절, 판매·재고 모두 없음, 자료 확인 필요 품목의 별도 처리 | 구현 |
| 확정 / 반려(이유) / 보류 결정과 덧붙이기 전용 기록, 엑셀 주문서 생성 | 구현 |
| 설정 점검, 데이터 정합성 점검, 실제 자료 투입 전 준비 점검 | 구현 |
| **품목별 미발주 예상 손실 금액 계산과 손실 기준 정렬** | 계획 |
| **발주 전후 기대 손실 비교** (과잉재고·폐기 비용 포함) | 계획 |
| **수요 예측 기반 최소 주문 금액 채우기** (부족한 금액을 어떤 품목으로 채울지) | 계획 |
| 품목별 주문 추이 화면, 품목 성과 주간 화면 | 계획 |

현재 정렬은 "곧 품절될수록, 필수일수록, 많이 팔릴수록 먼저"라는 규칙이며, 위의 손실 금액을 직접 계산하지 않습니다. 손실 금액 기준으로 바꾸려면 아래 값이 필요하고, 실제 데이터로 검증해야 합니다.
- 품절 기간 동안의 판매 손실 (재고 있는 날 기준 수요 × 단가 × 부족 일수)
- 대체 구매 여부(고객이 다른 품목으로 옮기는지), 마진, 폐기 단가

## 설계 원칙
- 판단은 **규칙 기반의 결정론적 계산**입니다. LLM을 쓰지 않고, 같은 입력은 같은 결과를 냅니다.
- **추천까지만** 합니다. 결정은 사람이 하고, ERP에는 쓰지 않습니다.
- 결정 기록은 지우지 않고 덧붙이기만 합니다.
- 품절 중의 판매 0은 수요 0이 아니므로, 수요는 재고가 있던 날의 28일 평균으로 추정합니다.

## 구성
- Python 3.11, pandas, DuckDB, Streamlit, openpyxl, pytest
- 입력: 일별 주문서·재고 기록·판매(POS)·상품 마스터 (CSV 또는 ERP 엑셀 내보내기 폴더)
- 승인 기록은 데이터 폴더마다 별도 DuckDB 파일에 저장
